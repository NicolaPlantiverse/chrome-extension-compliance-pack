WHAT IT CHECKS

The rejection reasons you can catch from the package.

Purple Potassium

Permissions declared but never called in the code, and the misunderstood ones the review flags: activeTab or tabs next to broad host access, tabs without reading URLs or titles, cookies or storage used only for document.cookie or localStorage.

Blue Argon · Red Titanium

Remote scripts, eval and remote imports; obfuscator output and encoded payloads. Minified code stays allowed.

Yellow Magnesium · Yellow Zinc

Packaging errors: manifest not at the ZIP root, missing icons, popup, options, side panel, content script or service worker files.

Purple Lithium · Nickel · Copper

Permissions that reach user data and therefore need a privacy policy and disclosure; network calls to plain HTTP or WS endpoints.

Firefox Add-ons

Missing gecko id (no signing for Manifest V3), missing or invalid data_collection_permissions (required for new submissions since 3 November 2025), service-worker-only background, bundled code that needs a source archive.

Microsoft Edge Add-ons

Names and descriptions that mention other browsers (policy 1.1.2), plus the same permission, privacy and obfuscation checks.

No. Chrome Web Store decisions depend on the full extension, the listing, the policies and the review. This is a deterministic preparation aid.

Where do the violation IDs come from?

From the official Chrome Web Store troubleshooting page. Each finding links the section it relates to, and the date of the last check is shown under the analyser.

No. It is not certified malware scanning, and the templates in the pack are documents to complete, not legal advice.
